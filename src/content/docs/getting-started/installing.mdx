When installing Lorealm, you have three main ways of doing so:
- Installing a pre-built binary
- Installing a Docker image
- Building from source

## Installing a pre-built binary
This approach is best for those who want to get up and running quickly, and only
plan to run the server locally. It's as simple as:
1. Head to the <a href="https://github.com/Lorealm/Lorealm/releases/latest" target="_blank" rel="noopener noreferrer">Downloads Page</a>
2. Install the binary for your Operating System
3. Move the downloaded file to a folder where you want to keep it
4. Run the executable file

When running the executable file directly, it will open a terminal window. The first time
you open it, it's going to walk you through an interactive setup process. Navigate with
the arrow keys on your keyboard and click Enter to select.

The simplest way to get started is to:
1. Select "Local Use"
2. Enter your account's Username and Password
3. Say yes to scaffolding resources

That's it. You're now up and running. You should see a message like:
```
Server starting on 127.0.0.1:1551
```
Simply open this URL in your browser and you're up and you should see the login page.

Log in with the Username and Password you entered earlier, follow the setup steps on
screen, and have fun!

## Installing a Docker image
This approach suits people who want to host Lorealm as a server on a dedicated server.
It gives you easy updates and lets you use the full feature set of Docker.

If you're new to Docker, it's recommended to read their
<a href="https://docs.docker.com/get-started/" target="_blank" rel="noopener noreferrer">Getting Started Guide</a>.
The rest of this section will assume you have Docker installed and have at least a
basic understanding of how it works.

The easiest way to get started is with a Docker Compose file. Here's a template:
```
services:
  lorealm:
    image: ghcr.io/lorealm/lorealm:latest
    restart: unless-stopped
    ports:
      - "1551:1551"
    volumes:
      - lorealm:/lorealm
    environment:
      # Creates the admin account on first start; ignored afterwards.
      LOREALM_ADMIN_USERNAME: admin
      LOREALM_ADMIN_PASSWORD: change-me
      # Uncomment (with the postgres service below) to use Postgres instead of SQLite.
      # LOREALM_POSTGRES_URL: postgresql://lorealm:lorealm@postgres/lorealm
    # depends_on:
    #   postgres:
    #     condition: service_healthy

  # postgres:
  #   image: postgres:17
  #   restart: unless-stopped
  #   environment:
  #     POSTGRES_USER: lorealm
  #     POSTGRES_PASSWORD: lorealm
  #     POSTGRES_DB: lorealm
  #   volumes:
  #     - postgres:/var/lib/postgresql/data
  #   healthcheck:
  #     test: pg_isready -U lorealm
  #     interval: 2s

volumes:
  lorealm:
  # postgres:
```
*The template above may not always be up-to-date.*<br/>
*<a href="https://github.com/Lorealm/Lorealm/blob/main/docker-compose.yaml" target="_blank" rel="noopener noreferrer">You can always find the latest template here</a>*

Copy the text above into a file called `docker-compose.yaml`. Be mindful of the folder
you place it in. All paths are relative to this file.

A few options to select the release stream you're targeting. In the image, you'll see
the line that says:
```yaml
image: ghcr.io/lorealm/lorealm:latest
```
This is how Docker knows what version of Lorealm to install. If you ever want to change
this, you can change the `:latest` suffix into something else. See the table below for
details.

<details>
<summary>Docker Release Streams</summary>
| Suffix               | Target version |
|----------------------|----------------|
| :latest              | Targets the latest stable release. Use this if you prefer stable releases. (default) |
| :nightly             | Targets the latest GitHub commit. Use this if you prefer the latest cutting-edge updates. These updates may be unstable, so use at your own risk. |
| :v\<version_number\> | Pins the release to a specific version (f.ex `:v0.1.0`). You will not recieve automatic updates. Use if you prefer updating manually.
</details>

In the template, you'll see a few variables, most notably `LOREALM_ADMIN_USERNAME` and
`LOREALM_ADMIN_PASSWORD`. Either you need to make sure these are set on the first run,
or you'll need to run the docker container as an interactive process. We won't explain
how to do the latter here.

> NOTE: The username and password variables are only needed on the first run. You may
> delete them later.

The server should now launch. The offical frontend should be downloaded automatically
unless one already exists. When it's done, everything should be accessible at the
configured address (`http://127.0.0.1:1551` by default). Simply open the URL in your
browser, log in with your credentials, and complete the setup steps on screen. Have fun!
